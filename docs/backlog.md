- [x] [P1] [Bug] **Auto-Wiedergabe an die Wort-/Karten-Identität gekoppelt statt an das ganze State-Objekt** (Autor-Befund 2026-07-10, Desktop-Sichtprobe; Root Cause im Opus-Review 2026-07-10 festgenagelt). Symptom war: Lernmodus startet → erstes Wort wird zweimal abgespielt, ab dem zweiten Wort (nach „Weiter") nur einmal.

  **Root Cause (verifiziert durch Code-Analyse, nicht mehr offen):** Beide Screens nutzen `LaunchedEffect(state)` mit dem *gesamten* Screen-State als Key, um „bei neuem Wort einmal abspielen" auszudrücken (`LernmodusScreen.kt:82`, `PruefmodusScreen.kt:107`). Der Key ist zu grob: Er koppelt das Abspielen an *jede* Structural-Equality-Änderung von `state`, nicht an den Wortwechsel. Beim Start setzt `LaunchedEffect(Unit)` **zwei** State-Variablen nacheinander — erst `recordings` (Zeile 69, löst Recomposition #1 aus), dann `state = Running(session0)` (Zeile 73, Recomposition #2). Über diese zwei dicht aufeinanderfolgenden Recompositions startet Compose den `state`-basierten Effect für dasselbe erste Wort zweimal an (der Effect für Key `Loading` wird abgebrochen und für `Running(session0)` neu gestartet, während die erste `playCurrentWord`-Coroutine schon lief) → zwei `queue.play()` auf dasselbe Wort. Ab Wort 2 gibt es nur noch **einen** State-Write pro Übergang (`advance()` setzt nur `state`), deshalb tritt das Doppeln nur beim ersten Wort auf. Das erklärt das exakte Symptom.

  **Zusätzlicher, gleichartiger Fehler im Prüfmodus (beim Fix mit erledigen):** Dort feuert `LaunchedEffect(state)` auch beim **Aufdecken** neu, weil `reveal()` einen neuen `Running`-State (`revealed=true`) erzeugt, der sich strukturell vom vorherigen unterscheidet — d. h. das Antippen der Karte spielt das Wort ein weiteres Mal ab, obwohl es nur aufdecken soll. Derselbe Fix (Key = Karten-/Wort-Identität statt ganzer State) behebt beides.
